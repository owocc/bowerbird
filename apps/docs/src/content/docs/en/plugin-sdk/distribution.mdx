Native plugins are zero-build directories. Package `plugin.json`, the optional `index.js`, and locale files directly.

## Directory and ZIP

```text
my-plugin/
├── plugin.json
├── index.js
└── locales/zh-CN.json
```

```bash
zip -r my-plugin-v2.0.0.zip my-plugin
```

The ZIP root may be the plugin directory itself or wrap it in one folder; the installer flattens that automatically.

## Installation

- Settings → Plugins → **Install plugin…**, then enter an HTTP(S) or `file://` URL for `plugin.json` or a ZIP.
- Or place the plugin directory under `<UserDataDir>/plugins/` and scan.
- Official plugins are registered as built-ins in packaged builds; a local directory with the same id overrides the bundled copy for development.

## Updates and state

`<UserDataDir>/plugins/native-plugins.json` stores enabled/settings state. Uninstalling a remote plugin removes its directory; built-ins cannot be removed but can be disabled.

<Aside type="tip" title="No Vite/Rollup needed">
  If your plugin only declares a `native` renderer or exports plain ES module hooks, there is no build artifact: ship the source directory as-is.
</Aside>
