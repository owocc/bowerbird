# 手机分享标记实施报告

日期：2026-10-21
分支：`feature/mobile-share-intent`

## 1. ID 验证结论

条目 ID = 原始文件字节的 **SHA-256，大写十六进制（64 字符）**。

- `core/library.go:1309-1364`：`copyAndHashFile` 边拷贝边哈希，返回
  `strings.ToUpper(hex.EncodeToString(sha256.Sum(nil)))`。
- `core/library.go:1438`：单文件导入 `itemID := contentHex`；Base64/字节导入同路径
  （`core/library.go:1629-1669`）。
- `core/mobile_api.go:799-821`：上传接口用 `io.Copy` 原样落盘后交给
  `ImportFilesWithProgress`，不转码、不重编码，因此图片/GIF/视频/音频/文本均适用。
- 移动端上传的是收件箱里的同一文件（文本为 UTF-8 `.txt`），本地哈希与服务端一致。
- 上传响应本身包含 `items[].id`（`core/mobile_api.go:838-842`），实现优先用它，
  缺失时才退回本地 SHA-256，作为兜底。

## 2. 实现要点

### 2.1 标记存储

新增 `mobile/lib/services/share_tag_service.dart`：

- `ShareTagStore`：持久化到 `<应用文档目录>/share_inbox/share_tags.json`，
  结构 `{"version":1,"marks":[{"id","library","sharedAt"}]}`。
- 采用与收件箱索引相同的 `.tmp` → `rename` 原子写；损坏文件按空集合启动。
- ID 统一大写并校验 `^[0-9A-F]{64}$`；按库名隔离；上限 2000 条，超出淘汰最旧。
- `ShareTagService`：应用级单例，提供 `isMarked` / `mark` / `forget`；
  流式 SHA-256（`hashFile`）避免大视频占内存。
- 库键只使用库名，不含 IP，避免 Wi-Fi/Tailscale 切换导致标记失效。

### 2.2 打标记路径

`mobile/lib/services/inbox_service.dart` 的 `uploadEntries`：

- 每项上传成功后取响应 `itemIds.first`；响应没有 ID 时回退本地文件哈希。
- 标记写入成功后才把条目移出收件箱；上传失败不写标记。
- 逐项处理，部分成功只标记成功项。
- 分享后自动上传、收件箱手动上传、全部上传都经过该函数。
- 主页 FAB 的普通上传（`home_screen.dart`）不写标记。

### 2.3 UI

- 新增 `mobile/lib/widgets/share_tag_badge.dart`：黑底小 chip，分享图标 + 「分享」。
- 主页月份网格、搜索页网格：命中标记时在缩略图**左下角**显示，避开左上 GIF、
  右上视频/音频角标。
- 详情页底部信息栏显示「手机分享」chip；元数据抽屉增加「来源：手机分享」。
- 本地标记不进 `/api/v1/tags`、不参与现有筛选与标签列表。
- 详情页、长按预览删除成功后调用 `forget(id)`，避免同内容再次普通上传时误显示。

### 2.4 启动初始化

`main.dart` 在收件箱初始化后调用 `ShareTagService.init()`；标记初始化失败不会阻塞启动。

### 2.5 老条目回填

**不做回填**。上传成功后收件箱条目与本地文件即被删除，索引只保留事件 ID，
没有可用于重算哈希的文件路径。标记从本版本起对新上传生效。

## 5. 真机待验清单

1. 微信分享一张图片到「保存到 Bowerbird」→ 收件箱自动/手动上传 → 主页网格该条目出现
   「分享」角标。
2. 主页 FAB 普通上传同一张图片（或不同图片）→ 不出现角标。
3. 打开分享条目详情页 → 底部出现「手机分享」，元数据抽屉出现「来源：手机分享」。
4. 杀掉并重启 App → 角标仍在。
5. 切换资源库 → 不显示其他库的标记；切回后恢复。
6. 在手机详情页删除分享条目后再普通上传同内容 → 不出现旧标记。
7. GIF / 视频 / 音频分享条目：分享角标与原有类型角标不重叠。

构建时出现既有的 Kotlin Gradle Plugin 迁移警告（`mobile_scanner`、`share_plus`），
与本任务无关，不影响本次产物。

## 6. 已知限制与未处理项

- 标记按库名隔离；若桌面端改库名，旧标记不再显示（数据保留，改回同名库可恢复）。
- 桌面端直接删除条目时手机无法感知，标记会保留；内容寻址下同 ID 即同内容，
  按方案接受。手机侧删除已做清理。
- 本任务未改动收件箱的幂等、逐项上传、角标计数及桌面端任何接口。
