### 2. 优化手段与分析（`--analyze-size` 结论）
1. **ABI 分包（`--split-per-abi`）**：去除了 APK 中不同 CPU 架构共享的原生 `.so` 动态库冗余，直接砍掉 ~40 MB。
2. **代码混淆与摇树（R8 `minifyEnabled` + `shrinkResources`）**：
   - `classes.dex` 压缩至约 1.0 MB。
   - MaterialIcons 矢量字体自动 Tree-shaking：由 1.64 MB 骤降至 8.2 KB（减少 99.5%）。
3. **符号剥离（`--obfuscate --split-debug-info`）**：DWARF 调试符号与 Dart 映射表剥离至 `mobile/debug-info/`，未进入最终发布包。
4. **META-INF 清理**：排除了重复的 License、Version、Notice 等约数十 KB 冗余元数据。

### 3. ML Kit 打包方案评估说明
- **评估结论**：本期**坚决保留 Bundled ML Kit** 方案，暂不切换为 Google Play 服务动态分发的 Unbundled 方案。
- **技术原因**：目标用户主要为国行 Android 设备或未安装/受限 Google Play 框架的环境。Unbundled 方案依赖 Google Play 动态下载扫描模型，在国行设备上扫码会因网络受阻直接抛出 `MlKitException: Waiting for the barcode module to be downloaded` 且永远无法成功；Bundled 方案虽然多占用约 860 KB 模型体积，但具备 100% 离线可用性，稳定性第一。

## 三、相机 Bug 根因分析与修复方案

### 1. 现象复现与排查
- **现象**：Release 构建包打开扫码页调不起相机，部分设备黑屏或无响应，而 Debug 包正常。
- **排查步骤与根因**：
  1. **R8 代码混淆剥离（主因）**：Release 编译默认使用 R8 优化。`mobile_scanner` 内部通过反射调用 Google MLKit 与 AndroidX CameraX 框架组件（如 `ProcessCameraProvider`、`Camera2Config`）。由于缺乏完整的 Consumer ProGuard 声明，R8 将 CameraX 的生命周期管理类、Provider 提供器以及部分内部接口裁切，导致运行时抛出 `MissingPluginException` 或 `InitializationException: CameraX failed to initialize`。
  2. **Play Core 缺失警告引发构建中断**：Flutter 嵌入层包含对 Google Play Core 的弱引用，开启 R8 后由于无 Play Core 依赖直接报错，需配置 `-dontwarn com.google.android.play.core.**`。
  3. **Android 硬件特性缺失**：原 `AndroidManifest.xml` 未声明 `<uses-feature android:name="android.hardware.camera.any" android:required="false"/>`，在某些只有前摄、虚拟摄像头或特殊相机 ID 映射的机型上无法被系统分配硬件。
  4. **未捕获错误导致静默黑屏**：原 `MobileScanner` 组件未实现 `errorBuilder`，相机初始化受阻时默认渲染黑色矩形遮罩，没有任何错误日志或重试入口。

### 2. 具体修法
1. **添加完整 ProGuard / R8 保护规则（`mobile/android/app/proguard-rules.pro`）**：
   ```proguard
   -dontwarn com.google.android.play.core.**

   -keep class io.flutter.app.** { *; }
   -keep class io.flutter.plugin.** { *; }
   -keep class io.flutter.** { *; }
   -keep class io.flutter.plugins.** { *; }

   -keep class dev.steenbakker.mobile_scanner.** { *; }
   -dontwarn dev.steenbakker.mobile_scanner.**

   -keep class androidx.camera.core.** { *; }
   -dontwarn androidx.camera.core.**
   -keep class androidx.camera.camera2.** { *; }
   -dontwarn androidx.camera.camera2.**
   -keep class androidx.camera.lifecycle.** { *; }
   -dontwarn androidx.camera.lifecycle.**
   -keep class androidx.camera.view.** { *; }
   -dontwarn androidx.camera.view.**
   -keep class androidx.camera.** { *; }
   -dontwarn androidx.camera.**

   -keep class com.google.mlkit.** { *; }
   -keep class com.google.android.gms.vision.** { *; }
   -keep class com.google.android.gms.internal.mlkit_vision_barcode.** { *; }
   -keep class com.google.android.libraries.barhopper.** { *; }
   -keep class com.google.photos.** { *; }
   -dontwarn com.google.mlkit.**
   -dontwarn com.google.android.gms.**
   ```
2. **清单文件补齐特性声明（`mobile/android/app/src/main/AndroidManifest.xml`）**：
   ```xml
   <uses-feature android:name="android.hardware.camera" android:required="false"/>
   <uses-feature android:name="android.hardware.camera.autofocus" android:required="false"/>
   <uses-feature android:name="android.hardware.camera.any" android:required="false"/>
   ```
3. **ScanScreen 错误视图与重试机制**：
   配置 `MobileScanner.errorBuilder`，相机异常时展示友好卡片（区分权限未授与硬件繁忙），并提供「重试」按键重新启动相机控制器。

## 六、推送链路修复

### 1. 根因陈述（引用 `/tmp/bowerbird-v3-wsfix2-brief.md` 确诊结论）
主会话实测证明：移动端 WebSocket 鉴权、心跳、信封封装及局域网广播机制均正常工作。当桌面端或移动端执行上传并走入已有调用点时，移动端能瞬时接收到 `items_updated`。
推送同步失效的真正根因聚焦在广播覆盖面不足与移动端事件丢弃：
1. **PC 端广播覆盖面不足**：
   `core/library.go` 内 `notifyItemsUpdated()` 原先仅在 3 处被触发（`runConcurrentImportJobs`、`commitImportBatch`、`DeleteItem`）。以下素材集合与元数据变更路径未发送 `items_updated`：
   - `UpdateItemDetails`（原先仅发了 Wails 的 `library-items-upserted` 事件，未发 ws）
   - `MoveToTrash` 与 `BatchMoveToTrash`
   - `RestoreFromTrash` 与 `BatchRestoreFromTrash`
   - `EmptyTrash`
   - `DeleteFolder` 与 `RemoveItemFromFolder`
   - `AddItemToFolder`、`SetItemFolders`、`MoveItemToFolder`
   - `RenameItem`、`AddTagToItem`、`RemoveTagFromItem`、`SetItemTags`、`DeleteTag`
   - `SaveItemThumbnail`
   用户在 PC 上编辑属性、整理标签与目录、挪入/移出废纸篓时，移动端无法感知变更。
2. **移动端节流与生命周期丢包**：
   - `mobile/lib/screens/home_screen.dart` 的 `_loadItems` 开头存在 `if (_isLoading) return;` 硬拦截，在首屏或加载中到达的 ws 刷新通知被直接丢弃。
   - APP 从后台切回前台时缺乏 `WidgetsBindingObserver` 监听，既不检查 ws 是否因系统休眠断连，也不主动补拉刷新。

### 2. 改动清单
1. **PC 端核心方法补齐 WebSocket 广播（`core/library.go`）**：
   - 在 `UpdateItemDetails`、`MoveToTrash`、`BatchMoveToTrash`、`RestoreFromTrash`、`EmptyTrash`、`DeleteFolder`、`AddItemToFolder`、`RemoveItemFromFolder`、`SetItemFolders`、`MoveItemToFolder`、`RenameItem`、`AddTagToItem`、`RemoveTagFromItem`、`SetItemTags`、`DeleteTag`、`SaveItemThumbnail` 的成功路径结尾均补齐 `m.notifyItemsUpdated()`。
   - 遵循同操作只发一次原则：`PermanentDeleteItem` 内部调用 `DeleteItem`（已发通知），不重复发；`BatchRestoreFromTrash` 循环调用 `RestoreFromTrash`（已发通知），不重复发。
   - 加锁死锁自查：`notifyItemsUpdated()` 内部调用 `m.GetActiveLibrary()`（申请 `m.mu.RLock()`），所有补齐点调用前均已无锁（持有锁已解锁或早于调用前释放），无死锁风险。
2. **PC 端广播覆盖集成测试（`core/mobile_api_test.go`）**：
   - 新增 `TestMobileWebSocketItemsUpdatedCoverage`，连入真实 WebSocket 客户端后，分别调用 `UpdateItemDetails`、`MoveToTrash`、`RestoreFromTrash`，断言均能收到 `items_updated` 广播消息。
3. **移动端支持并发刷新防丢与切回前台重连补刷（`mobile/lib/`）**：
   - `mobile/lib/services/websocket_service.dart`：暴露只读状态 `bool get isConnected => _socket != null && _socket!.readyState == WebSocket.open;`。
   - `mobile/lib/screens/home_screen.dart`：
     - 混入 `WidgetsBindingObserver`。
     - 引入 `_pendingRefresh` 标志，在 `_isLoading` 为 true 且收到 `refresh: true` 时标记 `_pendingRefresh = true`，并在 `finally` 块中立即触发下一轮刷新，防止推送被吞。
     - 实现 `didChangeAppLifecycleState`：切回前台（`resumed`）时，若 ws 未连接则调用 `connect()`，并始终触发一次 `_loadItems(refresh: true)` 确保数据最新。

### 1. 删除接口（PC 端）

- `DELETE /api/v1/items/{id}` 接入 `core/mobile_api.go` 的 `handleItemDetail` 方法分发，内部调用既有 `MoveToTrash`：
  - 语义为「移入废纸篓」，桌面端可恢复；移动端不提供永久删除。
  - 成功返回 `{"status":"success","code":"OK","data":{"id":"...","inTrash":true}}`，广播由 `MoveToTrash` 内部的 `notifyItemsUpdated()` 完成，HTTP 层不重复广播。
  - 错误映射：`400 INVALID_ID`、`401 UNAUTHORIZED`、`404 NOT_FOUND`、`409 ERR_ITEM_ALREADY_TRASHED`、`503 ERR_NO_ACTIVE_LIBRARY`、`500 ERR_DELETE_ITEM_FAILED`。
- `core/errors.go` 新增 `ErrCodeItemAlreadyTrashed`。
- `core/library.go` 的 `MoveToTrash` 增加幂等保护：对象已在废纸篓时直接返回，避免二次调用把 `trashed_folders` 覆盖为空、导致桌面端恢复后丢失原目录。
- `MobileServerVersion` 由 `1.0.0` 升至 `1.1.0`；`mobile/API.md` 新增 4.4.1 节与错误码说明。

### 5. 风险与回滚

- 部分 OEM/微信版本对剪贴板 `content://` 读取态度不一：失败时保留「分享/下载」兜底，不引入自定义 ContentProvider。
- `video_player`（Media3）对 avi/wmv/rmvb 等容器支持有限：失败走错误态提示；后续如确有需要再评估 `media_kit`。
- 网格动图上限 8MB：超限保持静态缩略图，避免一次拉取数十 MB。
- 回滚点：删除接口回滚 `core/mobile_api.go` + `core/errors.go`（无数据库迁移）；剪贴板回滚 `MainActivity.kt`、manifest provider、`file_paths.xml`、`ApiService` 两个方法；视频/GIF 回滚详情页 `PageView` 分页逻辑与 `video_player` 依赖。
