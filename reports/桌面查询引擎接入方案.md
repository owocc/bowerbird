# 桌面查询引擎接入方案

> 分支：`feature/mobile-share-intent` ｜ 范围：`frontend/` 数据层 + `core/` 查询入口小改；不动 `mobile/`、不改查询语法

## 1. 盘点：桌面当前的内存二次处理

`LibraryWorkspace.tsx` 先 `GetItems("", sort)` 拉全库，再在 `filteredItems` 里逐项过滤，结果顺序沿用 `importedAt desc/asc`。

| 现有条件 | 查询语法表达 | 去向 |
|---|---|---|
| 搜索框（name/tags/extension/hex/note/prompt 子串） | 有（自由文本） | 改发查询；输入整体加引号转义，保持“字面搜索”，不把用户输入的 `tag:` 当语法 |
| 类型/颜色/方向/大小/has url/has note/文件夹下拉 | 有 | 改发查询 |
| 标签侧栏选中标签 / 仅看有标签 | `tag:` / `has:tag` | 改发查询 |
| 未标记 / 未分类 | `is:untagged` / `is:uncategorized` | 改发查询 |
| 评分 1–5 | `rating:` | 改发查询 |
| 评分 = 未评分(0) | **无**（语法仅 1–5） | 不改语法：桌面专用查询入口增加 `onlyUnrated` 附加谓词，与语法过滤 AND |
| 选中文件夹的“含子文件夹” | **无**（重复 `folder:` 是 AND，无法 OR） | 不改语法：桌面专用查询入口增加 `folderScope[]`（OR）附加谓词，与语法过滤 AND |
| 废纸篓 / 拖拽历史 | 引擎默认排除废纸篓；历史依赖全库索引 | 废纸篓保持原 `GetTrashItems` 路径；历史按记录的 itemId 逐个 `GetItem`（条数很少） |
| 侧栏总数、未标记/未分类数、总大小、顶部分类颜色、子文件夹封面 | 非筛选语义 | core 新增轻量聚合 `GetWorkspaceStats` 与 `GetFolderPreviews`，避免为统计再拉全库 |

其余无法由语法表达的“多文件夹 OR / 未评分”只加桌面查询入口参数，`/api/v1/query` 契约与 `ParseQuery` 语法不变。

## 2. 改造点

1. **core**：新增 `QueryWorkspace(query, sort, offset, limit, folderScope[], onlyUnrated)`，内部 `ParseQuery` + 现有 `QuerySpec.matches` + 附加谓词，返回 `{items,total,totalSize}`；分页上限沿用 500。新增 `GetWorkspaceStats`（总数/未标记/未分类/总字节/前 1000 条 top8 颜色）与 `GetFolderPreviews`（每组 folderScope 的总数 + 前 4 条）。旧 `GetItems`、`QueryItems`、HTTP 行为不动。
2. **frontend 数据层**：`PAGE_SIZE=200` 首屏只取第一页；虚拟滚动接近底部时按 `offset` 追加下一页，`hasMore = loaded < total`；筛选/排序/搜索（150ms 防抖）变化时从 offset 0 重取并丢弃过期响应。
3. **内存过滤退役**：活动库视图 `filteredItems = items`（服务端已过滤）；仅废纸篓、历史保留原有客户端过滤。全库 `indexCache` 只覆盖“已加载窗口”，不再常驻全库。
4. **界面零变化**：侧栏计数/总大小/颜色 chips/子文件夹封面改由聚合接口供数，数值与顺序保持原口径；DOM 结构、样式、交互不动。

## 3. 事件与分页共存

- `upserted / trashed` 到达时：先做现有乐观局部更新（新条目插入、删除项立即消失），再 **150ms 合并防抖**，按当前查询重跑“已加载页数”的窗口（offset 0..n-1 并行），整体替换并校正 total；请求带版本号，过期响应丢弃。
- 取舍：不做“逐条判断是否命中当前查询”的局部增量。桌面筛选组合多（含 OR scope/未评分），逐条判定等于在渲染进程复制一份查询引擎，易与 core 语义漂移；重跑窗口的代价是 O(已加载页) 次服务端查询，通常 1–5 页，换来确定正确。
- 滚动中事件到达时保持已加载深度，不把列表缩回首屏；已选中的 id 仍按 id 保留。

## 4. 测量方法（改造前后同口径）

- 脚本生成 5,000 条 seed 库（固定随机种子、固定尺寸/颜色/标签/文件夹分布、缩略图复用），同一库分别跑改造前（`11d1573`）与改造后构建。
- 冷启动到首屏可交互：`app.log` 的 session start → `Loaded library items`/首屏查询完成；全量浏览首屏渲染：同一条日志的查询耗时 + `Gallery TypedArray layout computed`。
- 典型搜索：`tag:x`、`color:#...` 各 3 次取中位数，记录 IPC 往返 + 前端提交（`logDiagnostic`）。
- 渲染进程内存：稳定 3s 后取 WebKit WebContent 进程 `ps -o rss`，前后各 3 次取中位数；另用 Go benchmark 记录全量 `GetItems` 与分页查询的序列化条目数/分配量作交叉验证。
- 构建/回归：`go test ./core/...`、`pnpm --filter bowerbird build`；截图自查布局。
